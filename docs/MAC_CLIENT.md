# Native macOS client (E62)

The source lives in `apps/macos/AgentBus`. It is a SwiftUI app for one configured AgentBus contact and routed agent. The project name is **AgentBus**, bundle ID `com.chrispatten.agentbus.mac`, minimum macOS 26.5. It shares no source with Peggy.

## Build and setup

On a Mac with macOS 26.5, Xcode 26.6, and XcodeGen:

```sh
cd apps/macos/AgentBus
xcodegen generate
xcodebuild -project AgentBus.xcodeproj -scheme AgentBus -destination 'platform=macOS' CODE_SIGNING_ALLOWED=NO build test
```

Settings (⌘,) has General, Connection, and Notifications tabs. Connection accepts a bus URL, app token, and optional bus token. **Test Connection** calls `/api/v1/app/health` with the typed values and shows "Connected as <contact>" or the error, plus the routed agent, agent slots, upload limit, and bus version. A successful test saves the tokens to Keychain and reconnects; changed tokens are also saved when the tab closes. With no stored token, the app opens Settings › Connection on launch, and the first successful test opens Main and closes Settings. General has **Open at login** and Quit; ⌘Q is in the app menu. Configure the bus as in [APP_ADAPTER.md](APP_ADAPTER.md). The default URL is `http://127.0.0.1:3000`; for a remote URL use HTTPS so the socket uses WSS.

## Client behavior

- The socket sends protocol v1 `hello` with the last applied durable sequence. On a dropped connection it retries with 1–30 second exponential backoff. Wake and a network path changing from unavailable to available trigger an immediate reconnect. A path update while already online does not restart the socket.
- Session and message events are stored in SwiftData, with the cursor updated in the same save as each event. A repeated event is ignored. `welcome.reset` reloads the session list and recent history, replacing the local cache at the server's latest sequence. Older history is fetched by cursor on request.
- **Main across rotations (E69, `MainContinuity.swift`).** The bus rotates Main's Claude session rows underneath one Main item ([APP_ADAPTER.md → Main](APP_ADAPTER.md#main-one-continuous-conversation)). The cache keeps one `CachedSession` for Main whose `id` follows the bus's current row; the rows it had before are its `formerIDs`, and `boundaries` records where each ended. `ChatStore.merge` re-keys Main when an unseen active Main row arrives (a rotation) and records an unseen ended row as a former row. Main fragments cached before E69 fold into the one item, keeping the highest read marker and re-paging history. Messages map to Main by `conversation_id` (`item(for:)`, `canonicalID`), so activity frames, acks and notifications that name any Main row land on the one item. Selection, window and notification IDs match through `answers(to:)`, so a selection on an old row follows Main. Main's draft and reply target are keyed by the Main sentinel (`draftKey`), not the row ID, so they survive rotation. A `session` event's `rotated` and a history page's `boundaries` both feed `boundaries`.
- Session list and history requests keep their `state`, `limit`, and `before` values in the URL query so the bus routes match correctly.
- Outgoing sends are stored with a stable `client_msg_id` before transmission. After a disconnect they are resent under that same ID until acknowledged. While offline, the transcript labels them **Waiting for connection** and displays the connection error with a Reconnect button. A rejection remains visible with its reason and a Retry action.
- **Choice buttons (E86).** History items and `message` events may carry `choices` (`prompt_id`, `items[{label, style?, copy_text?, url?}]`, `status` open|answered|expired, `chosen_index`) and, on an inbound tap row, `choice_answer` (`prompt_id`, `index`, `label`); see [APP_ADAPTER.md](APP_ADAPTER.md). Both decode with `try?`, so a malformed value costs only that field. They are cached as JSON on `CachedMessage.choicesJSON` / `choiceAnswerJSON` (no store migration), with two local-only fields: `choicePendingIndex` (the tapped button awaiting its ack) and `choiceError`. State reaches the view three ways, each by mutating the cached row so `@Query` redraws: a durable `choice` event (`data.message_id`, `data.choices`) replaces the row's `choices` in `ChatStore.apply` (an uncached message is skipped, its history page carries the state); `upsert` from a history page or a later `message` event refreshes `choices` on an existing row (the one field of a stored message it changes; unchanged JSON is not rewritten); and a reset reload inserts fresh rows. Any non-open state clears the local pending and error. `BusConnection.choose(message:index:)` sends `{"type":"choice","client_msg_id","prompt_id","index"}` only while connected, on an open prompt with a `prompt_id`, for a callback item (no `copy_text`/`url`), with no tap already in flight; it records `client_msg_id` → (message, index) in memory and sets `choicePendingIndex`. Taps are never queued or resent: a disconnect, `reconnect()`, `stop()` and launch drop in-flight taps and clear `choicePendingIndex` (the outcome arrives as a replayed `choice` event). A tap's ack is matched before send acks. `queued` or `command` marks the cached prompt answered with the tapped index until the `choice` event confirms it; `rejected` clears pending and sets `choiceError` from `ChoiceRejection.explain`: `expired`, `forbidden`, `not_found`, `invalid_choice` get a short sentence, any other reason "Couldn't send your choice: <reason>", and `already_answered` nothing (the `choice` event brings the state).
- Ephemeral `activity` frames drive each session's live state, and also overwrite the cached session's `activity`, so a stale snapshot from a session event can't keep the spinner going after the turn. `running` shows "Working · 0:24" with the frame's `tool_lines`; `queued` shows "Waiting for a free slot". An idle frame without `session_id` is matched by `conversation_id`. When the reply's message event arrives, the trail is stored locally on that reply as a "Used N tools · 41s" disclosure. The bus does not store trails, so replies reloaded after a cache reset have none, and the disclosure is hidden. Each frame's slot counts update the sidebar footer and inspector; the inspector also polls `/health` every 15 seconds while visible.

## Interface

The UI follows `_bmad-output/planning-artifacts/mac-client/design/DESIGN.md` using stock SwiftUI controls, system colors, and SF Symbols.

- **Window:** `NavigationSplitView` with a sidebar, detail, and a toggleable inspector (⌥⌘I, remembered per window). Default size 1280 × 800, minimum 900 × 560. Double-click a row or use ⌥⌘O to open a session in its own window.
- **New Conversation (⌘N or the ✎ button):** asks the bus for an empty, untitled topic and selects it. The transcript shows the "New Conversation" placeholder and the composer is focused. The bus names the topic from its first message; rename it with ⌘R. This needs a connection. There is no title sheet.
- **Sidebar:** Main, Conversations by last activity, and a collapsed Earlier section. Main is one row across its rotations and never appears under Earlier. Each row shows the channel symbol, title, and a line with channel, relative time, or "<date> · read only". It has one trailing indicator: working spinner, queued clock, unread badge, or lock. The footer shows "Connected · 4 of 5 slots busy" or "Offline · reconnecting". The context menu has Rename (app topics), Open in New Window, Stop, and Clear Session. The Clear confirmation on Main says "The agent starts a fresh Claude session. Main keeps its scrollback."; on other sessions it says the conversation moves to Earlier.
- **Toolbar:** title and subtitle ("Started Sep 28 · 142 messages", "Telegram · continuing from Mac", "Sep 21 · 38 messages · read only"); Stop, inspector, and More. While the socket is down, a red "Offline · retrying in 8s" pill appears.
- **Transcript:** follows new messages, tool lines, and your own sends while you are at the bottom. If you have scrolled up, it stays put. When the composer grows (more lines in the draft), a transcript that was at the bottom scrolls up with it so the newest message stays visible. Day labels; operator bubbles with Sending…, Queued, Delivered, Command, or "Not sent · <reason>" with Retry. Retry resends an unacknowledged send under the same ID; a bus rejection is final for that ID, so Retry sends it again under a new one. Hover anywhere over an agent reply to show **Copy**, which copies its Markdown source (the hover area is the full message row, via `.contentShape`, so the pointer can travel from the timestamp to the button). **Copy Message** is also in the context menu of agent and operator messages and is exposed as an accessibility action. `MarkdownView` is `Equatable` on its source, so hover changes don't re-parse or rebuild the body. Hover also shows "From Mac" or "via Telegram" when the arrival channel differs; agent replies as block Markdown (paragraphs, lists, headings, quotes, fenced code with Copy). **Selection model:** `MessageTextBuilder` renders each run of non-code blocks into one `NSAttributedString` shown in a read-only `MessageNSTextView` (`MessageTextView`, an `NSViewRepresentable`), so a selection spans paragraphs, headings, quotes, and list items, including markers, and can be extended with Shift-click or double-click-drag. Fenced code blocks stay separate views (header, Copy, horizontal scroll), so a selection stops at one. The text view replaces its text only when the message content changes, so hover and live-activity redraws keep the selection. It reports its fitted size to SwiftUI, hugging short text. Its context menu keeps the system items and adds **Copy Message**. Fonts carry real bold/italic/monospace traits and `.link` attributes so `MarkdownWriter` can turn a selection back into Markdown. Your own bubbles use the same view (white text) and render block quotes, lists, and headings; fenced code in them is shown as monospaced paragraphs; attachment cards with expired state; `/clear` and scheduled prompts as centered notes (in Main the operator's `/clear` gets no note, because the "New context · /clear" divider already marks it; the bus's "Context cleared…" reply still shows). Code blocks and Copy show "Copied" briefly. **Choice buttons** (`ChoiceButtonsView`, after an agent message's attachment cards): one full-width button per row, or two per row when every label is 12 characters or fewer, at most 420 pt (360 pt for two columns) wide. `style` tints the bordered button: `primary` accent, `success` green, `danger` red. A `copy_text` button writes to `NSPasteboard` and shows "Copied" for 1.5 s; a `url` button opens through `openURL` (http/https only, otherwise disabled); neither sends a frame. A callback tap goes through the `chooseChoice` environment closure set by `TranscriptView`, which is nil while the socket is not connected. States: open (enabled); pending (spinner on the tapped button, all disabled); answered (the chosen button prominent with a checkmark and not clickable, the others disabled); expired (all disabled, "Expired" caption); offline (callback buttons disabled; copy and link still work, since they need no bus); a rejection shows its sentence in red under the buttons. An inbound row with `choice_answer` is drawn as a centered `.choiceNote`, "You chose **<label>**" in the note style, instead of an operator bubble. Older pages load when the top is reached. A cache reset shows a reloading overlay. **Context dividers (E69, `ContextDivider.swift`):** Main's transcript shows messages from every Main row, with a "New context" divider before the first message of each new row, placed above that context's day label. The label comes from the ended row's boundary: "New context · after 12 h idle" for an idle rotation (the span runs from the old row's last operator message to its end, or to the next message when the end time is unknown), "New context · /clear", or plain "New context" when the bus gave no reason. Hovering shows when the previous Claude session ended. A session resumed from Earlier on this Mac shows the original's messages above a "Resumed from …" note. The bus doesn't link the two sessions, so this link is kept locally.
- **Composer:** a floating glass capsule with attach, a 1–8 line field, and send. The field is `ComposerTextView`, an `NSTextView` of its own in an `NSScrollView` (TextKit 1, plain text), not a SwiftUI `TextField`: the field's shared field editor scrolled a long draft back to its start when focus left, ignored the scroll wheel, kept a stale wrap width after a resize (text ran under the send button), and clipped the caret and descenders of the last line. The text view grows from one line to eight, then scrolls, including with the wheel when unfocused; 7 pt insets above and below keep the last line clear. `sizeThatFits` measures the draft on the coordinator's own off-screen text system, cached by text and width, and never touches the visible text view: resizing the visible view's text container during layout asked for another layout pass from inside the current one, and a large paste looped until AppKit threw `NSGenericException` ("more Update Constraints in Window passes than there are views in the window"). Scrollers are always overlay (`OverlayScrollView`), even with a mouse attached, so a scroller appearing past eight lines never narrows and re-wraps the text. `ComposerLayoutTests` drives the composer in a real `MainWindow` on preview fixtures: a large paste, ⌘V of rich text through the paste monitor, a 700-line CRLF plain-text paste, and blur/refocus. Losing focus leaves the scroll position and selection alone. Gaining focus by any route but a click in the text (Tab, Reply, a session switch, `focusRequest`) puts the insertion point at the end of the draft; a click places it where you click. A change to the draft from outside (a quote appended, a send, another session's draft) replaces the text and moves the insertion point to the end. The placeholder is a SwiftUI overlay shown while the draft is empty. Return sends; Shift-Return or Option-Return inserts a newline at the insertion point (replacing any selection, via `insertNewlineIgnoringFieldEditor`), and ⌘Z undoes it. Keys reach the composer through the text view delegate's `doCommandBy` (`ComposerKey`): Return, ↑/↓ and Tab for the slash list, Escape (closes the slash list or cancels a reply, never opens completions), and PgUp/PgDn, which page the transcript. Files can be added with ⌘O, drop anywhere on the detail column, or ⌘V in the composer, which attaches copied Finder files instead of pasting their names. Pasted rich text is converted to Markdown: bold, italic, code, strikethrough, links, and bullets. Double-clicking an attachment you sent from this Mac opens Quick Look; the file paths are remembered across launches. Files over the bus `max_upload_bytes` show "Over 25 MB" and are never uploaded. Typing `/` opens a popover of `/api/v1/app/commands`, aligned to the composer's left edge; use arrow keys to move, Return or Tab to complete, and Escape to close. A resumable Earlier session sends into a new copy, which is then selected. An unresumable one shows a read-only bar with **New Conversation**. Drafts are kept per session while the app runs.
- **Inspector:** channel, topic, agent, Claude session when the bus provides it, start time, message count, a slot bar, Clear Session (confirmed), and Cost.
- **Reply to a selection:** with text selected in a message, right-click → **Reply** or press ⇧⌘R (Session menu, enabled only while a selection exists in a session that accepts messages). The selection becomes Markdown through `MarkdownWriter` (bold, italic, code, links, headings, bullet and numbered lists with nesting, quotes, and blank lines between blocks survive), is formatted by `QuoteFormatter` (each line prefixed `> `, blank lines `>`, ending with an empty line), and is appended to that session's draft in `BusConnection.drafts`, after a blank line when the draft already has text. Replying again appends another quote. The selection is cleared and the composer takes focus with the insertion point at the end (set through the field's `TextSelection`, because focus alone can select the whole draft). `TranscriptSelection`, owned by the session view, tracks the one text view that holds a selection and clears the previous one when another starts, so a selection never spans messages. A quote is plain Markdown in the message body: it carries no `reply_to`, because one message may quote several others.
- **Reply to a message:** right-click an agent message or one of your own with nothing selected → **Reply** (also in the text view's menu, where it replaces the quote item when there is no selection). The message becomes the session's reply target in `BusConnection.replyTargets`, keyed like `drafts`, so it survives switching sessions while the app runs. A "Replying to you|agent: first line" bar with ✕ appears above the field, Esc in the field cancels it, and sending clears it. The `send` frame then carries `reply_to` (the message ID); the bus resolves and quotes it (200 characters, see `docs/APP_ADAPTER.md`), and the agent sees a `[Replying to …]` line with the target's time and source above the message. A slash command is sent without the reference. The reference is stored whole on the `PendingSend` row (`replyToJSON`), so the pending bubble shows its note and a retry keeps it; the exception is a `reply_target_not_found` rejection, where Retry sends the message without the reply. Sent bubbles, and agent messages the bus quotes (an agent reply to an earlier message rather than your latest one, see [APP_ADAPTER.md](APP_ADAPTER.md#replying-to-a-message-reply_to)), show a "↩ Replying to …" note (leading-aligned above an agent message), decoded from the optional `reply_to` on history and `message` events (a malformed one is ignored rather than dropping the message) and cached on `CachedMessage.replyToJSON`, so it appears after a reload and on other clients. Clicking the note calls the transcript's `revealMessage`, which pages in older history (this session, then the one it was resumed from) until the message is cached, scrolls to it with `scrollTo(id:)` (the `LazyVStack` is a `scrollTargetLayout`), and highlights it for about 1.5 seconds. ⇧⌘R does nothing without a selection.
- **Menus:** Session menu with Stop (⌘.), Clear Session (⇧⌘K), Rename (⌘R), and Reply (⇧⌘R, quotes the selection); Next/Previous Session (⌃Tab/⌃⇧Tab) in Window.
- **Notifications:** agent messages outside every on-screen session, or any while the app is inactive, notify with the session title and preview ("New message" when previews are off). Replays send one "N new messages while you were away" alert per session. Alerts group by session ID, a click selects the session, and permission is requested before the first alert. The Dock badge totals unread counts and updates from each session event, whether or not a window is open. New messages in a visible session are announced to VoiceOver.
- **Notifications diagnostics:** each alert attempt is logged to the unified log under subsystem `com.chrispatten.agentbus.mac`, category `alerts`, with the authorization status and any error. Use `log stream --predicate 'subsystem == "com.chrispatten.agentbus.mac"' --level debug` to see them.
- **Previews:** `PreviewSupport.swift` seeds the mockup data. The Snowflake session seeds a choice prompt in each state (answered with its "You chose" note, expired, rejected, pending, and open with styles, copy and link). It has `#Preview` blocks for Main (light), the Telegram session (dark, with inspector), choice buttons (Snowflake), Earlier read-only/offline, empty states, each Settings tab, composer tokens, send states, and sidebar rows.
